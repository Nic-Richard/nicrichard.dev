Miscellary

Social collecting platform

Live

A web and Android platform built around user-created trading card sets

Miscellary started with the idea of letting people turn almost any subject into a collectible card set. Creators design and publish sets, while other users collect them through packs and trade owned copies.

The project grew into a full web and mobile product with social features, collection management, and a shared card rendering system. A lot of the technical work has gone into keeping ownership, trading, published card data, and visual rendering consistent across both platforms.

Built around

A Django and PostgreSQL backend with transactional collecting and trading, paired with shared web/mobile card rendering and baked presentation assets.

Stack

TypeScript, Next.js, React Native, Expo, Django, PostgreSQL, Docker, AWS

TraceTray

Behavioural analytics

Live beta

Behavioural analytics from lightweight interaction data

TraceTray is built around the idea that you can derive a surprising amount of useful behavioural information from very little raw data.

A lightweight tracker collects simple interaction signals such as cursor movement, clicks, scrolling, and pauses. I then use machine learning and analysis pipelines to turn those signals into higher-level findings about attention, hesitation, movement, and engagement.

I then built a dashboard around those results, with behavioural insights, visual summaries, and AI generated summaries to make the analysis easier to interpret.

Built around

Using ML to extract useful UX signals from a lightweight stream of interaction data.

Stack

Node.js, Express, MongoDB, Python, scikit-learn, pandas

WikiRacr

Graph search and multiplayer game

Live

A competitive Wikipedia navigation game backed by fast graph search

WikiRacr started as a research project on graph search algorithms for finding shortest paths between Wikipedia articles.

I built forward and reverse link graphs and used bidirectional breadth-first search to reduce route finding time by orders of magnitude compared with the other approaches I tested. That made it practical to curate large numbers of start and goal pairs and put my own spin on the classic wikiracing game, with routes that are intentionally chosen instead of completely random.

From there, I built it out into a full game with Solo and Daily Challenge, plus multiplayer modes including Classic, Ranked, Speedrun, Knockout, Clicks, Score, and Higher or Lower.

Built around

Fast shortest-path search over Wikipedia’s link graph and curated article pairs at scale.

Stack

React, Vite, Node.js, Socket.IO, SQLite, Clerk, Stripe

Portlore

Geographic data and travel planning

Live, data in progress

A cruise-port guide built around what makes each stop worth exploring

Cruise passengers often only see the obvious attractions near a port and miss the smaller places that give a destination its character.

I built Portlore to make those places easier to find. It starts from where passengers actually disembark, gathers nearby points of interest, and narrows them into a practical set of recommendations that includes both major sights and worthwhile local finds. The app then helps passengers turn those into a realistic plan for the time they have ashore.

Built around

Finding and curating useful places around cruise ports, then turning them into practical day plans.

Stack

JavaScript, Node.js, Express, OpenStreetMap, Google Places and Routes, Anthropic
